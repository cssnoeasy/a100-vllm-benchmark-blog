# KV Cache 显存分配均衡性检查记录

## 这组记录回答的问题

旧博客里有一组关于 KV Cache 显存分配不均的排查材料。整理到主项目后，这部分不再写成“发现并解决了一个通用问题”，而是写成一次检查：在本项目的 Qwen2.5-7B TP2 实验中，是否观察到两张 A100 的 KV Cache 或显存明显不均。

## 已观察到的事实

| 项目 | 结果 |
| --- | --- |
| 模型 | Qwen2.5-7B-Instruct |
| 并行方式 | TP2 |
| GPU | 双 NVIDIA A100 80GB PCIe |
| 显存观测 | 两张卡均约 74003 MiB |
| Attention heads | 28 个，可被 TP2 整除 |
| 本次结论 | 未观察到明显显存不均 |

这组结果只说明本项目当时的模型、并行度和负载条件下没有发现明显不均。它不是对所有模型结构、vLLM 版本或张量并行度的通用证明。

## 背景解释

KV Cache 的分配是否均衡，和模型结构、head 数量、并行切分方式、vLLM 版本以及配置参数都有关系。Qwen2.5-7B 的 28 个 attention heads 能被 TP2 整除，这降低了按 head 切分时出现明显不均的可能。

社区 issue 或其他项目中出现的 KV Cache 分配不均，可以作为背景知识，但不能直接写成本项目自己的实测结果。公开报告里只保留自己测到的内容。

## 不能从这里推出什么

- 不能说 vLLM 所有版本都不存在 KV Cache 分配不均。
- 不能把社区案例中的具体数字当成本项目数据。
- 不能把未经验证的参数建议写成稳定解决方案。
- 不能把“未发现不均”写成“已经证明完全均衡”。

## 工程实践要点

这部分可以说明我会检查多卡部署里的显存分布，而不是只看总显存是否够。对系统工程岗位来说，更重要的是排查意识：看到多卡性能或容量问题时，要同时看模型切分、KV Cache、head 数量、拓扑和实际指标。
