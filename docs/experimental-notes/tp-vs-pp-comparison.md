# TP2 与 PP2 补充对比记录

## 这组实验回答的问题

这组补充实验来自早期博客材料，目标是比较同样使用两张 A100 时，张量并行 TP2 和流水线并行 PP2 在 vLLM 推理中的表现差异。

它的价值不在于给出“所有场景选 TP”的结论，而在于把并行方式放到同一硬件、同一模型、同一类负载下做过对照，帮助解释为什么后续主项目把 TP1/TP2 作为正式基线主线。

## 实验条件

| 项目 | 内容 |
| --- | --- |
| 硬件 | 双 NVIDIA A100 80GB PCIe |
| 模型 | Qwen2.5-7B-Instruct |
| 框架 | vLLM |
| 对比方式 | TP2 vs PP2 |
| 负载一 | 短文本场景 |
| 负载二 | 长文本场景 |
| 备注 | PP2 侧启用了 `--enable-chunked-prefill` |

## 观测结果

| 场景 | TP2 吞吐 | PP2 吞吐 | 观察 |
| --- | ---: | ---: | --- |
| 短文本 | 2.86 req/s | 1.37 req/s | TP2 高于 PP2 |
| 长文本 | 2.80 req/s | 0.98 req/s | TP2 高于 PP2 |

在这组实验条件下，TP2 在短负载和长负载中的请求吞吐都高于 PP2。

## 我如何解释这件事

PP2 会把模型层切到两张卡上，流水线需要依赖微批调度来提高设备利用率。对于 Qwen2.5-7B 这种单卡可容纳的模型，如果负载规模、batch 形态和调度条件没有把流水线填满，PP 的分层执行可能无法抵消调度和跨卡传递开销。

这个解释与流水线气泡、调度开销的常见机制一致，但本次实验没有直接测量 bubble ratio，也没有用 profiling 把每个阶段的等待时间拆出来。因此这里把它写成“与机制一致的解释”，而不是写成已证实根因。

## 不能从这里推出什么

- 不能写成 TP 在所有双卡部署里都优于 PP。
- 不能写成 PP 任一时刻最多只有一张卡工作，或者 GPU 利用率不超过 50%，因为本实验没有给出这样的直接测量。
- 不能把“流水线气泡”写成唯一根因。
- 不能把这组 PP2 数据和正式 TP1/TP2 基线混成同一张严谨对比表，因为负载、参数和实验版本不完全等价。

## 工程实践要点

这组实验可以说明我实际比较过并行策略，而不是默认多卡推理只有 TP 一种做法。我的判断是：如果模型单卡能放下，是否使用多卡并行要看负载和尾延迟；如果必须切模型，还要区分 TP、PP、量化、KV Cache 扩容等不同手段的代价。
