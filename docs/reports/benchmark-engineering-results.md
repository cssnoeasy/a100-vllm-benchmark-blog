# Benchmark 工程化与已完成特性验证

**状态：** 已完成的工程验证与有限特性对照  
**证据等级：** B  
**范围：** 单卡 vLLM 的配置驱动执行、结果校验、质量门禁，以及 Prefix Caching 和 Chunked Prefill 的已有记录

## 1. 问题与边界

主项目不仅需要一次性能测试，还需要回答“结果能否被管理、检查和解释”。第 4 周至第 5 周已经完成了配置驱动的实验执行链：服务启动、就绪检查、热身、GPU 指标采集、结果归档、状态校验、汇总和质量门禁。

本报告只整理已经完成的记录。Prefix Caching 与 Chunked Prefill 的数据是特定环境和负载下的有限对照，不是所有模型、所有请求分布或线上默认配置的推荐结论。

## 2. 已完成的工程闭环

一次运行由配置和运行 ID 约束，runner 负责启动服务、等待就绪、执行负载、保存结果并写入状态。结果汇总时保留 `planned`、`starting`、`failed`、`stopped`、`completed`、`validated` 等状态，只有通过校验的运行才进入正式汇总表。

已有记录证明以下环节已经实际执行：

| 环节 | 已完成证据 | 说明 |
| --- | --- | --- |
| 服务就绪检查 | `week5_single_gpu_2048x512_c1_readiness_fail_v2` | 服务在就绪前退出时，被记录为 `failed`，错误为 `returncode=1` |
| 单卡基线运行 | `2048x512`、并发 4 和 16 的多次运行 | 保存请求完成数、吞吐、TTFT、TPOT 和 GPU 采样 |

| 质量门禁 | 吞吐不低于可比基线的 80% | `PASS`、`WARN`、`SKIP` 分开保留，不把告警结果隐藏 |

## 3. 单卡与 TP2 runner 记录

在 `2048x512`、并发 16 的已校验运行中，单卡输出吞吐为 `945.08 tok/s`，p99 TTFT 为 `2430.69 ms`，p99 TPOT 为 `16.42 ms`；TP2 输出吞吐为 `1187.75 tok/s`，p99 TTFT 为 `2578.79 ms`，p99 TPOT 为 `12.88 ms`。两条 c16 记录在相对于历史基线的质量门禁中均为 `WARN`，因此它们用于展示 runner、校验和告警机制，不替代第 3 周三次重复的正式 TP1/TP2 基线。

单卡 `2048x512`、并发 4 的多轮已校验记录稳定在约 `328.38` 至 `329.69 tok/s`，16 个请求均完成且失败数为 0。这些运行的质量门禁为 `PASS`，说明该负载下的 runner 重复执行与归档链路可用；它们仍属于工程验证，不应与正式三重复对照报告混为一类。

## 4. Prefix Caching：已有重复观察

实验在并发 16 下记录了 4 类请求组成，每类 3 次运行，并以两次热身后的结果汇总。数据如下：

| 请求组成 | 重复数 | 热身后输出吞吐（tok/s） | 热身后 p99 TTFT（ms） | 热身后 p99 TPOT（ms） |
| --- | ---: | ---: | ---: | ---: |
| 随机 `1024+0` | 3 | 1258.87 | 237.36 | 11.61 |
| 前缀 256 + 后缀 768 | 3 | 1118.51 | 282.94 | 11.85 |
| 前缀 512 + 后缀 512 | 3 | 1192.39 | 277.32 | 11.73 |
| 前缀 768 + 后缀 256 | 3 | 1142.53 | 261.47 | 11.75 |

### 解释

共享前缀长度不同，对应的吞吐和 TTFT 存在差异；`512+512` 的吞吐最接近随机请求，而 `256+768` 的离散度较大。已完成记录不能证明“前缀缓存一定提升性能”，因为这里没有与完全一致负载下的关闭对照，也没有覆盖缓存命中率、不同并发和真实请求分布。

## 5. Chunked Prefill：已有开关对照

在并发 16 下，已完成两次开关运行，并以一次热身后结果汇总：

| 配置 | 重复数 | 热身后输出吞吐（tok/s） | 热身后 p99 TTFT（ms） | 热身后 p99 TPOT（ms） |
| --- | ---: | ---: | ---: | ---: |
| 开启 | 2 | 1243.77 | 342.26 | 12.39 |
| 关闭 | 2 | 1251.25 | 356.27 | 12.38 |

这组数据下，两种配置的吞吐和 TPOT 接近；开启时的热身后 p99 TTFT 略低。由于有效热身后样本各只有一次，且关闭路径曾产生兼容性警告，不能将差值推广为全面优劣，更不能写成默认配置建议。

## 6. 质量门禁的价值

质量门禁不负责制造更好看的曲线，而是防止异常运行悄悄进入结论。已有记录中：

- 单卡 c4 多轮基线、短时持续请求和 Chunked Prefill 开关运行均为 `PASS`。
- 单卡 c16 与 TP2 c16 相对历史基线低于 80% 门槛，记录为 `WARN`。
- 共享前缀运行因没有对应的同口径基线，记录为 `SKIP`，而不是强行给出通过或失败判断。
- 一次服务在 readiness 前退出，保留为 `failed`，没有被伪装成空白或成功运行。

这套状态保留使后续读者能区分“运行过”“校验过”“与基线可比”和“可用于正式性能结论”四件不同的事。

## 7. 局限

1. 本报告的特性记录不是完整的三重复开关消融，不能作为统一调参建议。
2. runner 记录和第 3 周正式 TP1/TP2 实验的模型、版本、负载与基线口径必须分别阅读。
3. `WARN` 只表示触发当前质量门禁，不等于定位到根因；不得据此推断为硬件、NUMA、NCCL 或框架问题。
4. 工程验证证明流程被实际使用，不等于证明所有异常、网关行为或生产容量边界都已覆盖。
