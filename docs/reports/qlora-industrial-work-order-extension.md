# QLoRA 合成工业工单训练与离线评测扩展

**状态：** 已完成训练和离线评测记录，未形成在线服务闭环  
**证据等级：** C  
**范围：** 主线之外的受限扩展，不替代 A100 推理服务结论

## 1. 为什么纳入项目

该扩展把公开的结构化设备维护事实转换为可审计的合成工单任务，训练 QLoRA adapter，并在留出的合成文档案例上评估结构化输出。它的价值在于明确展示“模型适配”和“在线推理服务”是两条不同的工程链路。

它不证明多 adapter 在线 vLLM 服务、adapter 加载延迟、adapter 隔离、回滚、真实工业工单或真实 OCR 部署，以上内容均不在本报告范围内。

## 2. 数据与任务边界

公开来源为 UCI AI4I 2020 Predictive Maintenance 数据集，提供的是结构化设备和故障事实，而不是企业真实工单叙事。工单 schema、优先级、路由、审批规则、文档载体、OCR 损坏、冲突案例和提示注入案例均为合成实验设计，不能表述为真实工业工单性能。

主项目不纳入原始数据压缩包、处理后的训练数据或 adapter 权重，避免许可证和公开范围不清的问题。

## 3. 训练与离线评测摘要

记录使用单张 A100 80GB、Qwen2.5-7B-Instruct 和 NF4 QLoRA。实验经过三个版本：

| 版本 | 目的 | 已记录结果 |
| --- | --- | --- |
| v1 | 结构化 AI4I 记录到 JSON 工单草稿 | 基础表格模板检查通过，但留出的文档硬案例暴露出文档与 OCR 处理缺口 |
| v2 | 增加文档载体并独立评估文档 | 留出合成文档验证 all-core 为 46/48；固定硬案例为 4/8 |
| v3 | 继续进行文档策略训练 | 留出合成文档验证 all-core 为 48/48；固定硬案例为 6/8 |

面对严重 OCR 情况，v3 更倾向于输出空字段并要求人工复核，而不是断言无法辨认的事实；仍有 2 个严重 OCR 硬案例未通过严格 schema 检查。这是安全倾向和评测边界，不是生产就绪结论。

## 4. 从结构化事实到评测闭环

这组扩展的工作流分为四步：先将 AI4I 的设备状态、故障类型和维护相关字段整理为可追溯的结构化事实；再按预先定义的工单 schema 生成合成任务描述、优先级和路由字段；随后使用 NF4 QLoRA 训练 adapter；最后在未参与训练的合成文档和固定硬案例上检查字段、约束和 all-core 结果。

v1 的目标是先验证结构化事实能否转换为 JSON 工单草稿。v2 将文档载体与独立文档评测加入闭环，暴露出 OCR 损坏或字段冲突时的处理缺口。v3 围绕这些失败样本调整文档策略，使留出合成文档的 all-core 从 46/48 提升到 48/48，固定硬案例从 4/8 提升到 6/8。版本迭代记录的是离线任务规则和评测覆盖的变化，不应被解读为真实产线指标。

## 5. 为什么是 C 级证据

历史记录包含训练参数、结果、脚本、配置与详细评测规则，但公开主项目尚未迁入可复现的运行 manifest、评测输出、adapter 产物或服务基准。因此它是边界清楚的训练扩展，不能与主线 A100 TP1/TP2 正式报告按相同强度比较。

## 6. 结论边界

该材料证明已经完成合成工业工单的 QLoRA 训练迭代和离线评测，不证明在线 adapter serving。留出验证和硬案例应保持不变，训练损失也不能替代业务验收。
