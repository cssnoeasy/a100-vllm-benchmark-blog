# 证据与表述规范

## 证据等级

| 等级 | 含义 | 公开表述 |
| --- | --- | --- |
| A | 正式受控实验，有冻结配置、重复、原始结果和完整汇总 | 可以写“实验表明”，同时注明适用条件 |
| B | 工程验证、Smoke、故障恢复或离线业务回放 | 写“已验证链路/行为”，不要外推为生产结论 |
| C | 探索性实验、源码阅读、单轮对照或资料整理 | 写“观察到/初步结果”，不能写成普遍规律 |
| D | 计划、设计、未完成任务或交接事项 | 只能写“计划/待完成” |

## 每篇报告的固定顺序

问题与边界 -> 环境 -> 方法 -> 证据 -> 结果 -> 解释 -> 局限 -> 复现入口。

任何百分比都要说明基线、指标方向、聚合方式、样本数量和实验条件。`max-concurrency` 不得写成 RPS；GPU 利用率不得直接写成成本效率；E2E 不得写成 TPOT；离线业务回放不得写成真实机器人端到端。

## 不可越界的事实

- TP2 结论只适用于报告中的 A100 PCIe、无 NVLink、跨 NUMA、vLLM 版本、模型和合成负载。
- 第 7 周巡检回放只覆盖视觉识别和图谱检索之后的文本推理。
- TensorRT-LLM 资料验证的是 PyTorch backend 服务链路，不是 serialized TensorRT engine。
- 没有正式结果的 Kubernetes、Coding Agent、流式取消、用量记账和生产入口，不得写成已完成。
- 不能把历史内网环境和访问方式带入公开仓库。
