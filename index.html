01 / DEPLOYMENT BASELINE

不是先选配置，而是先建立对照

主线基于双 NVIDIA A100 80GB PCIe，GPU 间无 NVLink、跨 NUMA 的拓扑，使用 Qwen2.5-7B-Instruct 与 vLLM 0.19.0。TP1 与 TP2 在三类固定合成负载下各重复三次，共 18 轮、1,800 个请求；指标同时覆盖吞吐、TTFT、TPOT、端到端延迟和运行状态。

实验问题做法得到的工程判断
单卡还是双卡TP1 / TP2 受控对照，三类负载各重复 3 次TP2 绝对吞吐提高，但不把多卡写成默认答案
轻负载尾延迟记录 TTFT、TPOT、E2E 的 p50 / p95 / p99发现反例后保留异常，不用平均吞吐掩盖
配置是否可信冻结环境、保存 run ID、原始结果、采样和校验记录结论可回溯到条件、数据和汇总口径

02 / OPTIMIZATION DECISIONS

优化同时看资源、SLO 与质量

量化专题使用单张 A100 上的 Qwen3-32B，与 TP1 / TP2 的 Qwen2.5-7B 主基线分开统计。专题将 BF16、FP8 KV Cache、官方 AWQ 与 self W4A16 GPTQ 放进统一矩阵：先测模型加载显存和 KV 容量，再用闭环并发和开环 SLO 阶梯测服务能力，最后用固定 500 题做质量回归。

-70.5%self W4A16 加载显存

61.03 GiB 降至 18.03 GiB。

5.49xGPU KV token 容量

self W4A16 相对 BF16。

-6.0 pt固定 500 题质量

self W4A16 相对 BF16 的代价。

部署结论不是“量化越小越好”。 self W4A16 在指定 SLO 下最高已验证 request-rate 为 1.3 req/s，BF16 为 0.6 req/s；但它的固定题集质量从 83.60% 降至 77.60%。容量收益必须与业务质量门禁一起判断。
