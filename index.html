01 / 核心实验

双卡并行，收益来自哪里

在两张无 NVLink、跨 NUMA 的 A100 PCIe 上，对 Qwen2.5-7B-Instruct 做 TP1 与 TP2 的受控对照。每种负载重复 3 次，共 18 轮、1800 个请求，所有轮次均成功完成。

观察项已验证结果解释
绝对吞吐+33.42% ～ +44.71%三类合成负载均提升
重负载 TPOT p99−31.15%长输入、长输出、高并发
重负载 E2E p99−28.37%尾延迟同步改善
!

不能忽略的反例 长输入短输出时 TTFT p50/p95 上升 5.43%/5.29%；短负载 TPOT p99 上升 59.93%。TP2 使用两张 GPU，因此不能直接推导单位 GPU 效率更高或双卡全面更快。

02 / 核心实验

显存换容量，也换来质量代价

量化实验同时记录模型加载显存、GPU KV token、固定 SLO 下的容量和固定 500 题质量集。这样可以把“省了多少显存”和“能不能多接请求”放在同一张决策表里。

BF1661.03 GiB加载显存 · 39,200 GPU KV token
→
self W4A16 GPTQ18.03 GiB加载显存 · 215,344 GPU KV token
5.49×GPU KV token 容量
+116.7%最高 request-rate
−6.0 pp固定质量集
i

另一条路径 BF16 + FP8 KV Cache 将 GPU KV token 从 39,200 提升到 78,400，固定 500 题质量仍为 83.60%。它优化的是 KV 容量，不是权重量化。

03 / 核心实验

用 SLO 定义“能多服务多少”

容量结论使用固定约束：失败请求为 0、P99 TTFT 不超过 4000 ms、P99 TPOT 不超过 60 ms。满足这些条件时，BF16 最高已验证 0.6 req/s，self W4A16 最高已验证 1.3 req/s。

失败请求0
P99 TTFT≤ 4000 ms
P99 TPOT≤ 60 ms
质量集500 题

“最高已验证”只表示在本次阶梯和本次环境中通过的最高点，不等于理论上限，也不等于生产容量承诺。
